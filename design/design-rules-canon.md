# Канон правил генерации (черновик — на согласование)

Источник: `designMd` документа — дизайн-система **Skala Spectrum** (8.8 КБ markdown,
70 формулировок), плюс `do`/`don't` манифеста кита. Ниже те же требования,
но приведённые к виду **правило = id + уровень + формулировка + чем проверяется**.

**Уровни:** `Требуется` — без этого экран неверен; `Запрещено` — нарушение;
`Предпочтительно` — отклонение допустимо, но должно быть названо.

**Проверка:**
- **Д** — детерминированно, по документу (цвет, токен, размер, тип узла, наличие `ref`);
- **С** — структурно (число экранов, пустые фреймы, дубли);
- **С-LLM** — суждение проверяющей модели по этому же id.

## Состав и способ сборки

| id | ур. | правило | проверка |
| --- | --- | --- | --- |
| G-01 | Требуется | Мастера кита — только `type:"ref"` + `descendants` по слотам; не рисовать контрол фреймом | Д |
| G-02 | Запрещено | Тянуть generic design-system-composition (сайдбар 240–280, pad 32, `$color-accent`) | Д |
| G-03 | Требуется | **Нет пустых корневых фреймов**; нет дублей панелей/оболочки | С |
| S-01 | Требуется | **Один экран на запрос.** Если запрос не называет несколько («два экрана», «страницы», flow) — второго корневого экрана быть не должно; правка идёт в существующий | Д (число корней + запрос) |
| G-04 | Требуется | Варианты переключаются на существующем инстансе, а не пересобираются | С-LLM |
| G-05 | Предпочтительно | Ничего лишнего на холсте: то, что не просили — замечание | С-LLM |

## Чего в каноне намеренно нет

- Вкусовых суждений («красиво», «современно») — они не проверяются и не должны
  попадать в правила.
- Требований, которые сегодня нечем проверить и некому судить: каждое правило
  выше помечено Д / С / С-LLM. Если правило нельзя проверить ни одним из трёх
  способов — это не правило, а пожелание, и в каноне ему не место.

## Что даёт канон

- Промпт получает короткий список «id + одна строка» вместо 8.8 КБ текста:
  сейчас в промпт из правил кита идёт **2 «do» и 1 «don't» на тип**.
- Каждое замечание проверяющего ссылается на id — и человеку понятно, что
  именно нарушено, и цикл правок получает точную инструкцию.
- Появляется место для детекторов: правило без детектора видно сразу.
